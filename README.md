# Inmanta language support for Zed

Syntax highlighting for `.cf` files in the [Zed](https://zed.dev) editor,
based on a Tree-sitter grammar derived from the official Inmanta PLY parser and also partially generated by claude opus ai.
The grammar this extension points to can be found here: https://github.com/DariushMoh/tree-sitter-inmanta.

As explained, the grammar was partially generated using ai which means it may not be entirely stable/correct. Any improvement/feedback is welcome.

## Requirement

Make sure you have `rustup` installed on your system.
After that execute `rustup-init`. 

## Installation

1. Git clone this repository
2. Open Zed.
3. Open the command palette (`Ctrl+Shift+P` / `Cmd+Shift+P`).
4. Run **`zed: install dev extension`**.
5. Select the zed-inmanta-extension directory you just cloned.

Zed will compile the grammar to WASM and activate the extension.
Open any `.cf` file to verify syntax highlighting is working.

## Language Server

### Setup

1. Install inmantals in your env:
```bash
   source .env/bin/activate
   pip install inmantals setuptools wheel
```

2. Add to your Zed project specific `settings.json`:
```json
   {
     "lsp": {
       "inmanta-language-server": {
         "settings": {
           "pythonPath": "~/.virtualenvs/my-env/bin/python"
         }
       }
     }
   }
```

### Troubleshooting
It may be that the features of language server do not work and no obvious errors can be found in `zed > open log` menu.
In this case this command may be handy:
```
ls -t /tmp/vscode-inmanta-*.log | head -1 | xargs grep -i "compil\|error\|success\|anchor" | tail -200
```
it will show any error from the language server logs, this may be helpful to debug it.
It will most often be due to some missing python packages in the env.
